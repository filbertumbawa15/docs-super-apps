API Lookup Pengajuan SKCK & Izin Keramaian

Satu endpoint untuk mengambil profil singkat pemohon beserta riwayat pengajuan SKCK dan Izin Keramaian berdasarkan NIK. Dipakai oleh aplikasi eksternal yang sudah punya App-Id dan Access-Key.

POST/api/v1/external/service-applications/lookup

Mulai cepat #

  1. Minta APP_ID dan Access-Key ke pengelola API.
  2. Kirim request POST berisi NIK ke endpoint lookup.
  3. Baca data.user, data.skck, dan data.crowd_permit dari respons, lalu tampilkan.
curl -X POST "$HOST/api/v1/external/service-applications/lookup" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json" \
  -H "App-Id: $APP_ID" \
  -H "Access-Key: $ACCESS_KEY" \
  -d '{"nik":"0000000000000001","page":1,"per_page":20}'

Autentikasi #

Setiap request wajib membawa dua header identitas. API ini tidak memakai skema Bearer.

HeaderWajibIsi
App-IdwajibAPP_ID aplikasi pemanggil yang terdaftar.
Access-KeywajibToken akses, dikirim apa adanya tanpa awalan Bearer.
Content-Typewajibapplication/json
Acceptdisarankanapplication/json

Jangan taruh Access-Key di frontend produksi. Siapa pun bisa membaca header dari browser. Panggil API ini dari backend Anda, lalu teruskan hasilnya ke halaman.

Mengembalikan profil pemohon dan daftar pengajuan untuk NIK yang dikirim. Layanan yang tidak diminta tetap ada di respons sebagai array kosong, jadi bentuk respons selalu sama.

Paginasi #

info berisi current_page, per_page, total, dan last_page. Nilai total adalah gabungan SKCK dan izin keramaian. Contoh: 1 SKCK + 1 izin keramaian menghasilkan total: 2.

Contoh kode #

async function lookup(nik, services) {
  const res = await fetch(`${HOST}/api/v1/external/service-applications/lookup`, {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      'Accept': 'application/json',
      'App-Id': APP_ID,
      'Access-Key': ACCESS_KEY,
    },
    body: JSON.stringify({ nik, services, page: 1, per_page: 20 }),
  });
  if (!res.ok) throw new Error(`HTTP ${res.status}`);
  const json = await res.json();
  return json.data; // { user, skck, crowd_permit }
}
use Illuminate\Support\Facades\Http;

$response = Http::withHeaders([
        'App-Id'     => config('services.layanan.app_id'),

        'nik'      => $nik,
        'services' => ['skck', 'crowd_permit'],
        'page'     => 1,
        'per_page' => 20,
    ]);

$data = $response->throw()->json('data');

Komponen Bootstrap #

Komponen di bawah ini dipakai di halaman tampilan data. Semuanya memakai class Bootstrap 5.3 standar, tanpa CSS tambahan.

Badge status

Petakan nilai status ke label dan class text-bg-*.

const STATUS = {
  waiting_payment:    ['Menunggu Pembayaran', 'text-bg-warning'],

  completed:          ['Selesai',             'text-bg-primary'],

const badge = s => {
  const [label, cls] = STATUS[s] || [s, 'text-bg-secondary'];
  return `<span class="badge rounded-pill ${cls}">${label}</span>`;
};

Catatan & pertanyaan terbuka #

Nama variabel token di koleksi Postman tidak konsisten. Auth koleksi memakai {{Token}}, tetapi setiap request mengirim header Access-Key: {{AccessKey}}. Variabel AccessKey tidak didefinisikan, sehingga header bisa terkirim kosong.

  • Waktu: submitted_at dalam UTC, timestamp dalam WIB. Konversi ke WIB sebelum ditampilkan.
  • Tipe ID: SKCK memakai ULID string, izin keramaian memakai integer.
  • Paginasi gabungan: belum jelas bagaimana per_page dibagi antara dua array. Perlu dikonfirmasi ke tim backend.
  • Kode error: format respons untuk 401, 404, dan 422 belum ada di koleksi.
  • URL dokumen: application_path relatif. Perlu dipastikan base URL dan apakah unduhan butuh autentikasi.

Disusun dari koleksi Postman "External Service Applications - SKCK dan Izin Keramaian". Data pada contoh adalah data uji.
