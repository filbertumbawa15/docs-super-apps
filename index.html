API Lookup Pengajuan SKCK & Izin Keramaian

Satu endpoint untuk mengambil profil singkat pemohon beserta riwayat pengajuan SKCK dan Izin Keramaian berdasarkan NIK. Dipakai oleh aplikasi eksternal yang sudah punya App-Id dan Access-Key.

POST/api/v1/external/service-applications/lookup

Mulai cepat #

  1. Minta APP_ID dan Access-Key ke pengelola API.
  2. Kirim request POST berisi NIK ke endpoint lookup.
  3. Baca data.user, data.skck, dan data.crowd_permit dari respons, lalu tampilkan.
curl -X POST "$HOST/api/v1/external/service-applications/lookup" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json" \
  -H "App-Id: $APP_ID" \
  -H "Access-Key: $ACCESS_KEY" \
  -d '{"nik":"0000000000000001","page":1,"per_page":20}'

Autentikasi #

Setiap request wajib membawa dua header identitas. API ini tidak memakai skema Bearer.

HeaderWajibIsi
App-IdYaAPP_ID aplikasi pemanggil yang terdaftar.
Access-KeyYaToken akses, dikirim apa adanya tanpa awalan Bearer.
Content-TypeYaapplication/json
AcceptDisarankanapplication/json

Jangan taruh Access-Key di frontend produksi. Siapa pun bisa membaca header dari browser. Panggil API ini dari backend Anda, lalu teruskan hasilnya ke halaman.

Endpoint lookup #

POST{{host}}/api/v1/external/service-applications/lookup

Mengembalikan profil pemohon dan daftar pengajuan untuk NIK yang dikirim. Layanan yang tidak diminta tetap ada di respons sebagai array kosong, jadi bentuk respons selalu sama.

Parameter body #

FieldTipeWajibKeterangan
nikstringYaNIK pemohon, 16 digit.
servicesstring[]Tidak"skck", "crowd_permit", atau keduanya. Jika tidak dikirim, keduanya diambil.
pageintegerTidakNomor halaman. Default 1.
per_pageintegerTidakJumlah data per halaman. Default 20.

  "per_page": 20

estimated_days_remainingintegerSisa hari masa berlaku dihitung dari hari ini.

Paginasi #

info berisi current_page, per_page, total, dan last_page. Nilai total adalah gabungan SKCK dan izin keramaian. Contoh: 1 SKCK + 1 izin keramaian menghasilkan total: 2.

Endpoint kredensial SKCK #
